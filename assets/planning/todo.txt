Current planned efforts, in order:

1. Do the first extensive code cleanup and elegance boost.

  1.1. Get rid of bad patterns:

    - Clumps of bookkeeping variables being passed around, along with the data
      structure they describe, instead of having an object for said structure,
      with member functions cleanly handling adding elements, finding an
      element, reallocating the data structure with more memory, etc.

      Four data structures come to mind that neede this improvement: The Code
      Block Directory, the Statement Directory, the IR Instructions Directory
      and the custom memory arena - a region where different sized, but related,
      objects are placed next to each other in memory. So far we have two:
        - AST Arena
        - IR Instructions Arena

    - Repetitive code, for instance when emitting IR instructions for BinOps.

    - Inconsistent ownership transfer when moving to the next compiler phase.
      Make all ownership of large data structures be transferred via move
      semantics. So far, at these borders: Lexing -> Parsing -> IR Generation.

  1.2. Establish a clean coding style, apply it to all existing project code.

  1.3. Comments may need to be added, adjusted or reduced in some places.
       Go over the whole existing codebase and make sure all comments are OK.

2. Come up with and implement a proper compiler driving program and stages.
   Source code should come from files. Compiler phases should be separately
   spawned OS processes on intermediate files or interprocess communications.

   This will let the separate compiler phases be analyzed in detail by tools
   like Top-down microarchitecture analysis and will let them be cleanly
   separate programs, as well as separate operations when compiling a program.

   Update the compiler source code files and Makefile to build the programs
   for the different phases separately.
